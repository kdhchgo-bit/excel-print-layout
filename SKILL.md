# Excel print layout

Prepare the requested workbooks for legible printing. Treat the actual PDF and reopened Excel file as the evidence, and keep the source, the visible table, its data and its external-link targets intact. Work on a named copy unless the user explicitly requests another arrangement. Respect the user's exact scope and exclusions; do not turn project-specific sizes or page counts into defaults.

## Workflow

1. **Scope and baseline.** Enumerate only the requested files/sheets; honor recursion and exclusions. Record SHA-256, file format, sheet order and visibility, effective hidden rows/columns, merges, used/print areas, breaks, shapes and external links. Keep hidden items hidden throughout unless the user explicitly requests otherwise. Read [references/architecture.en.md](references/architecture.en.md) or the equivalent [Korean reference](references/architecture.ko.md) for the full layers, tasks, gates and repair mechanisms.
2. **Plan by visible content.** Identify complete tables, headers, merged groups and drawings, including the intentionally nonprinted calculation area. Measure printed width and height after accounting for hidden rows/columns. Choose A4 orientation, margins and scale based on readability and page use. One page is appropriate for a small table; do not force an extensive table into unreadable type. For a wide table, split only at logical group boundaries when needed and repeat identifying columns and complete headers; protect merged cells, borders and data coverage. Consider the requested paper size if it is not A4.
3. **Make a concrete, repeatable plan.** Use [assets/print-plan.example.json](assets/print-plan.example.json) as a structural example, replacing every value with inspected facts. Specify absolute target widths/heights, scale, margins, print area, repeated titles and breaks rather than repeated multipliers. Compare the existing file state before changing it. Never add duplicate page breaks or repair shapes; identify only assistant-owned repair objects and avoid touching user shapes. Do not apply width/height changes to hidden rows or columns: Excel can silently unhide them.
4. **Execute safely.** On Windows use a separate native Excel COM instance to preserve legacy `.xls`, formula caches, macros, drawings and links. Disable macros/events and link updates, set manual calculation after creating a blank workbook if needed, and open the source read-only. SaveAs a same-format copy in its intended destination so Excel can rebase relative links; verify that the actual link targets still resolve to the intended originals. Do not recalculate unless requested. Record the instance PID; quit only that instance. Avoid launching excessive Excel instances or a Python file named `inspect.py`.
5. **Render, reopen and repair.** Reset only unwanted breaks and rebuild intended breaks from the plan. Check `PrintCommunication` changes and re-read settings after save/reopen: the saved zoom can differ from the requested one. Export each printable sheet to PDF in a temporary/deletion folder, measure A4/page count/ink footprint/text and inspect every page at suitable resolution. Check half-clipped text, `###`, merged headers, group borders, drawings, repeated titles, blank pages and content coverage. Fix real defects and re-run the affected checks; do not assert that an automated text audit proves visual integrity.
6. **Verify and deliver.** Compare all source and output sheets, effective hidden states, merged ranges, cell values, formulas/caches, and link targets. Use `scripts/compare_workbooks.py` for an independent read-only structural comparison and `scripts/compare_excel_com.py` for Excel formula/value/link checks when native Excel is available. Use `scripts/audit_pdf.py` as a triage aid, not a substitute for visual inspection. Reopen the final output, verify its final hash, then deliver the copies with a short account of page splits, unchanged original links, and any real readability or verification limits. Report unrelated source-data discrepancies separately without changing them.

## Progress and idempotence

Maintain one per-workbook ledger with `scripts/progress_ledger.py` and a plan tied to the source SHA-256. See [references/ledger-usage.md](references/ledger-usage.md) for working commands and sheet-catalog coverage. Record actual evidence files for each workbook gate and each printable sheet's plan, PDF and visual review. A workbook is complete only after all source-catalog sheets are classified, all required gates pass, every printable sheet is covered, and the final source/output/plan/evidence hashes still match. On a rerun, if those hashes and the current request fingerprint match and the ledger says `verified`, skip mutations and reuse the verified output. If the source, request, plan, output or evidence changed, invalidate the affected gates and rebuild from the original into a new staged copy; never repeatedly widen columns, enlarge fonts, add lines or split an already modified output. Never overwrite an unrelated existing output.

The scripts report their own coverage and missing dependencies. A successful structural comparison is not proof of uncut text, matching external links or an actual printed page. The ledger records evidence and hashes; it cannot independently prove a person's visual review.
